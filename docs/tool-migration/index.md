# 🔄 工具迁移与协同

> **目标**：用过别的 AI 编程工具（Cursor、Copilot、Codex、ChatGPT 网页版……）？这一章帮你把已有经验平移过来，少走重复学习的弯路。

## 📜 本章概览

市面上的 AI 编程工具大致分三种形态：

- **独立编程 Agent**：独立运行的智能体，命令行或自带桌面 App——Codex、Gemini CLI、OpenCode、Aider 等，以及 Claude Code 本身
- **IDE 内嵌助手**：长在编辑器里——Cursor、Copilot、Windsurf、通义灵码、文心快码、CodeBuddy
- **网页版 AI**：浏览器对话框——ChatGPT、Claude.ai、各类国产网页大模型

Claude Code 属于第一种。你从哪种形态转过来，适应成本差别很大——这一章**按来源分别给迁移路径**，最后再讲一个进阶话题：不止用一个工具时，怎么让它们配合干活。开始前请先[装好 Claude Code](/getting-started/)。

## 🧱 先懂这四件事

不管你从哪来，这四点是 Claude Code 区别于大多数工具的底层设定，后面每条路都会反复用到：

| # | 核心设定 | 它意味着什么 |
|---|---------|-------------|
| 1 | **它是终端 Agent，不是补全引擎** | 你不是边打字边接受建议，而是**给一个任务，它自己读文件、改代码、跑命令**，把事情做完 |
| 2 | **上下文要你主动给** | 它不会自动索引整个仓库。你用 `@文件`、`CLAUDE.md`、`!命令` 把它需要的东西喂进去（见 [2.5 →](/basics/file-references)）|
| 3 | **权限系统管着它的手** | 读 / 写 / 执行命令分级管控，危险操作会停下来问你（见 [2.4 →](/basics/permissions)）|
| 4 | **CLAUDE.md 是它的长期记忆** | 把项目约定写进去，不用每次重讲。几乎每个工具都有类似 rules 文件，可直接搬（见 [2.7 →](/basics/claude-md)）|

::: tip 两个须知
- **计费有两种模式**：Claude Code 既能用订阅套餐（Pro / Max，按月固定，和 Cursor 包月逻辑接近），也能用 API Key 按 token 用量计费。走用量这条路才需要适应"用多少花多少"，用的时候留意 `/cost`。
- **MCP 配置基本可复用**：你在别的工具里配过的 MCP 服务器，配置大体能平移过来（见 [2.12 →](/basics/mcp-servers)）。
:::

## ⚖️ 该不该完全换过来？

不必非此即彼。Claude Code 有它的主场，也有它不擅长的地方：

- **它强在**：多文件成规模改动、自己跑命令验证、复杂任务自主推进，以及 Hooks 自动化、Worktree 并行、扩展思考这些独有能力
- **它弱在**：边打字边给行内补全（inline autocomplete）——这块 Cursor、Copilot 仍然更顺手

所以一个常见且高效的姿势是：**Claude Code 干 agentic 的重活，IDE 助手管行内补全的轻活，双管齐下。** 怎么配合而不打架，就是 5.4 的内容。

## 🏆 通关战利品

打完这一章，你将能够：

- 把原工具的操作习惯快速对应到 Claude Code，不用从零学
- 看懂 Claude Code 和原工具在机制上的根本差异（上下文、权限、计费）
- 把旧工具的规则文件（`AGENTS.md` / `.cursorrules` 等）平滑搬成 `CLAUDE.md`
- 判断什么任务该用 Claude Code、什么任务原工具更合适
- 设计多工具协同方案，让多个工具配合提效
