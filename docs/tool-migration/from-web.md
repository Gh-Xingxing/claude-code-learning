# 5.3 从网页版 AI 迁移

> **预计耗时**：12 分钟

## 本关任务简报

如果你之前主要在浏览器里用 AI 写代码——**ChatGPT、Claude.ai、文心一言、通义、Kimi** 这些网页对话框，那么 Claude Code 会带给你一个颠覆认知的转变。

你熟悉的流程是这样的：把代码**复制**进对话框 → AI 给你改好的代码 → 你再**复制**回编辑器 → 自己跑、自己调。AI 全程看不见你的项目，也碰不到你的电脑。

Claude Code 最根本的不同是：**它直接读写你电脑上的真实文件，还能自己跑命令。** 不用再复制粘贴来回搬运——你指给它哪个文件，它直接改；要验证，它自己跑。

这一关帮你完成从"问答"到"派活"的心智转变，并守住安全底线。

## 机制解析

### 根本差异：它在你的电脑里干活

| | 网页版 AI | Claude Code |
|--|----------|-------------|
| 看得到你的文件吗 | 看不到，要你复制粘贴 | **能，直接读你指定的文件** |
| 能改你的文件吗 | 不能，给你代码你自己贴回去 | **能，直接写到磁盘** |
| 能跑命令吗 | 不能 | **能，自己跑测试 / 安装依赖 / git 操作** |
| 记得你的项目吗 | 每次对话基本从零开始 | 靠 `CLAUDE.md` 记住长期信息 |
| 运行在哪 | 云端 | **你的电脑上** |

这个差异意味着三件事：

1. **不用再贴代码**——用 `@文件名` 指给它，它自己读。
2. **它能闭环**——改完能自己跑起来验证，发现错了能自己接着修，不用你当二传手。
3. **改动落在真实文件上**——所以需要权限系统和 git 来兜底（下面讲）。

---

### 心智转变：从"问答"到"派活"

网页版用久了，你的习惯是**问问题**："这段代码怎么优化？""帮我写个函数做 X。"

Claude Code 更适合**派任务**："把 `@src/utils.ts` 里的日期处理函数重构一下，加上时区支持，然后跑一遍测试确认没破坏现有用例。"

区别在于：你不再是问它要答案然后自己执行，而是**把一整件事交给它在你的电脑上完成**。任务描述得越完整（要做什么、改哪些文件、用什么标准验收），它干得越好（提示词技巧见 [3.12 →](/advanced/prompt-advanced)）。

---

### 安全边界：能力越大，越要兜底

正因为它能真的改文件、跑命令，新手要先建立两道防线：

**第一道：权限系统**

Claude Code 在写文件、跑命令前会停下来问你。**保留这个确认**，看清它要做什么再放行。

> ⚠️ 别一上来就用 `--dangerously-skip-permissions`（全程免确认）。这个模式适合你已经很熟、且在隔离环境里跑，新手用容易出事（见 [2.4 权限系统 →](/basics/permissions)）。

**第二道：git**

重要的项目先用 git 管起来。这样即使 Claude 改错了，`git checkout` 一下就能还原。没有 git 的项目，至少先备份。

```bash
git init
git add .
git commit -m "接入 Claude Code 前的存档"
```

---

### 你需要准备的：本地环境

网页版 AI 不要求你电脑上有任何东西，Claude Code 不一样——它在你的真实项目里干活，所以你得有：

- 项目代码在本地（不是只在某个网页里）
- 对应的运行环境（比如 Node.js、Python 等，取决于你的项目）

如果你连项目都还没有，先随便建个文件夹、放几个文件，让 Claude 在里面练手也行。

---

## 开始闯关

**目标：把一件你平时会在 ChatGPT 里问的代码任务，改成让 Claude Code 直接在真实文件上完成。**

**第 1 步：进入一个真实项目**

```bash
cd 你的项目目录
claude
```

没有项目就新建一个文件夹，放一两个代码文件进去。

**第 2 步：用 `@` 指文件，而不是粘贴**

回想你上次在 ChatGPT 里贴了一大段代码问的问题。这次别贴，直接指：

```
@你要改的文件 帮我[你上次问的那件事]
```

**第 3 步：让它自己验证**

```
改完之后跑一下 [你的测试 / 启动命令] 确认没问题
```

观察它怎么自己跑命令、看结果、必要时接着修——这是网页版给不了的闭环。

**第 4 步：看清每一次确认**

留意权限确认弹窗，读懂它要改什么、跑什么命令再放行。建立"看清楚再放行"的肌肉记忆。

## 卡关了？翻车指南在这

**"它怎么不知道我整个项目有啥？"**

它不会自动读全部文件。把相关文件用 `@` 带进来，或写一份 `CLAUDE.md` 告诉它项目结构（见 [2.7 →](/basics/claude-md)）。这和网页版"每次重新贴"是两种逻辑——这里是一次写好、长期生效。

**"我电脑上没装运行环境，它跑命令报错"**

Claude Code 在你真实的电脑上跑命令，所以该装的环境（Node、Python 等）得先装好。可以直接问它："我要跑这个项目需要装什么？帮我列出步骤。"

**"它要权限我有点慌，会不会乱改？"**

刚上手时，保留权限确认是对的——你能看清每一步再放行，再配合 git 兜底，最坏也能一键还原，不必慌。

但要诚实说一句：每步都确认确实影响流畅度。等你熟悉之后会发现，很多人（包括重度用户）会切到"跳过权限确认"的 bypass 模式（`--dangerously-skip-permissions`）换取顺畅，把安全完全交给完全信任的项目工作区或者 git 来兜底。权限的几种模式和各自的适用边界，见 [2.4 权限系统 →](/basics/permissions)。

**"习惯了一问一答，不知道怎么'派活'"**

把任务说完整：做什么、改哪些文件、做完怎么算成功。一开始可以先在 plan 模式（`Shift+Tab`）让它只规划不动手，你看过方案再放行。
